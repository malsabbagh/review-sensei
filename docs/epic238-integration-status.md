# Epic238 integration status

This draft assembles the independently reviewed source components for
[#238](https://github.com/malsabbagh/review-sensei/issues/238). It is a reader and
test integration, not an activation of partitioned authority or a declaration of
250-finding hosted lifecycle support. New partition writers remain disabled.
No merge, release, channel movement, or publisher environment approval is part
of this draft. The separately authorized merged-main release excludes these
unmerged changes.

## What the consumer integration changes

CLI recovery, GitHub application recovery, and the observed-workflow harness
reconstruct baselines through the authenticated ledger reader. A missing trusted
resolver, damaged part, or incompatible authority withholds reuse. Reading does
not rewrite the stored inventory or its identity. The hosted source guard uses
the human adapter's complete source identity fence, including numeric actor,
association, and inline parent metadata.

Hosted evidence acquisition uses the exhaustive adapter with base/head and
changed-file-count fences. Its integrated rich route must receive the original
shared read guard; separate phases cannot replenish the allowance. Actual Git
paths containing literal glob characters retain exact equality throughout
models, context, coverage, evidence, and verification. Configured path-pattern
rules retain their existing semantics.

Shared documents are serialized once with exact content, digest, and per-lens
references. Work identity includes both the shared-document format and the
whole-supplemental context policy. Mandatory documents are retained in full;
finite refusal remains appropriate when the mandatory prompt cannot fit.
Context omissions remain visible and prevent complete-review approval.

## Blockers before writer activation or complete-evidence qualification

1. Persisted control accounting currently omits activation-tail work. Independent
   consuming-grant measurements stored 10 calls while 16 had occurred, and then
   stored 24/39 while 31/46 had occurred. A bounded nonrefundable tail liability
   and safe pre-root failure/restart contract must be reviewed and implemented.
   Recursive snapshots or a fresh allowance on restart do not solve this.
2. Five checkpoint activations exceed the original 64-dispatch envelope even
   for tiny journals. Proposed coalescing to three is not a hosted acceptance
   result. The measured three-save path persists accepted state at 39 GitHub
   dispatches but the local path refuses at 52 before accepted durability. These
   are lower bounds excluding source, provider, grant issuance, acknowledgement,
   and other evidence. The strict original 60-second activation horizon remains.
3. Each hosted root mutation requires a fresh consuming broker grant, exact
   source/head/generation checks, owned readback, and ambiguous-outcome
   reconciliation. Mutable root generation must not change operation identity.
   GitHub's guarded replacement is not atomic compare-and-swap.
4. Joint queue throughput, 32 retained source operations, 2 MiB journal size,
   root capacity, retained objects, and scan budgets need complete multi-event
   qualification. If only four findings fit each source operation, 250 findings
   need 63 distinct operations, exceeding the current registry. Preserve prior
   obligations and tombstones rather than evicting them to mint capacity.
5. Complete feedback, exact explicit target selection, queue persistence,
   publication root activation, and source acknowledgement still need the
   consuming-grant public full/reply/command lifecycle tests. Same logical
   comment events with edited content or targets must not mint new operation
   budgets. The default hosted mention remains the legacy 4 KiB route.
6. V4 eligibility readers remain a fail-closed prototype; finalization withholds
   until the authenticated host activation contract is qualified. Latest broken
   authority must never fall back to an older clean root.
7. Exact installed wheel/npm/action qualification, historical reader inventory,
   reader-first migration and delayed-job drain, and actual deployed observations
   remain separate gates. Source tests do not prove rollout.

The existing documented policy permits eligibility without a published check
when checks permission is unavailable. Epic238's broader missing-check negative
requires an explicit product-policy disposition. This draft preserves the
documented behavior and makes no branch-protection satisfaction claim.

## Release qualification sequence

Freeze the source and run the complete credential-free CONTRIBUTING gates,
then build and identify exact artifacts. Run the extracted installed consumer
suites outside the checkout, including baseline/eligibility/full/reply/command
readers. Qualify the consuming-grant lifecycle and fault matrix at the same
source head. Inventory alternate and delayed readers before enabling new
writers; retain old authority and history during migration. Only claim the
profiles demonstrated through publication, restart, human assessment, and
finalization under the original budgets. A pending result is the correct
outcome when any complete authority or resource proof is unavailable.
